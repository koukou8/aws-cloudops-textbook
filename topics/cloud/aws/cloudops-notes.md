# AWS CloudOps クイックメモ

AWS CloudOpsで混同しやすいサービス仕様を、短い箇条書きで確認するためのメモです。

## CloudFront

### キャッシュインバリデーション

- エッジロケーションに保持された指定パスのオブジェクトを強制的に削除
- 次回のリクエスト時にオリジン（S3）から最新のコンテンツを取得させる
- 即座にキャッシュをクリア
- 既定ではクッキーをオリジンに転送しない

## NAT Gateway

- 作成直後のNAT Gatewayは「Pending」状態
- 通信を処理できるのは「Available」状態に到達してから
- 処理できるプロトコルはTCP、UDP、ICMPに限られる
- Elastic IPを割り当てて利用

## Route 53

- CNAME：apexドメインは設定不可
- ALIAS：apexドメインに設定可能。CloudFront、ALB、S3などへ向けるRoute 53独自機能

## ELB

- リージョン内で完結する

### ALB

- スティッキーセッションはターゲットグループの属性として設定可能

## Auto Scaling

- 単一のリージョン内で動作する

### シンプルスケーリングポリシー

- 1回のスケーリングアクティビティを実行した後は、デフォルトのクールダウン期間（300秒）が発生

## WAF

- CloudFront向けの「グローバルスコープ」と、ALBやAPI Gatewayなどリージョン単位のリソース向けの「リージョナルスコープ」の2種類
- 関連付けられるのは、CloudFront、Application Load Balancer、API Gatewayなど限られたサービス

## S3

- `s3-bucket-logging-enabled`ルール
  - S3バケットのサーバーアクセスログ設定を継続的に評価し、ロギングが無効なバケットを非準拠として検出
- サーバーアクセスログ
  - 配信先はS3のみ
- 長距離転送はTransfer Acceleration
- マルチパートアップロードは、1つの大きなオブジェクトを複数のパートへ分けて並列送信
- CRR
  - 既存オブジェクトは対象外。S3 Batch Replicationを使う
- イベント通知はLambdaを直接の宛先にできる

## AWS Systems Manager

### Run Command

- SSM Agentが動作しているEC2インスタンスに対して、コンソールやAPIから任意のコマンドを一括実行できるサービス
- 同時実行数を制御する仕組みが「レートコントロール」
- `max-concurrency`パラメータで、同時にコマンドを配信するインスタンス数を絶対数または割合で指定

### Session Manager

- SSHやRDPのプロトコルを使わずに、ブラウザまたはAWS CLI経由でインスタンスのシェルにアクセスできる機能

## AWS CodeDeploy

- EC2、Lambda、Amazon ECSへのデプロイを自動化

### Blue/Greenデプロイ

- 本番トラフィックを移す前に、古いバージョンと一緒に新しいバージョンを用意
- 問題があれば、終了前の元のインスタンスへトラフィックを戻せる

### In-placeデプロイ

- 同じインスタンス群へ新リビジョンを順に適用する方式
- 新旧のフリートを並行して持たない

## EC2

### プレースメントグループ

- 単一リージョンで機能する
- クラスター型
- パーティション型

## セッションアフィニティ（スティッキーセッション）

- 同じ利用者からのリクエストを常に同じサーバーへ送る仕組み

## VPCエンドポイント

- どちらもインターネットを経由しない

### ゲートウェイ型

- S3とDynamoDBのみ対応
- 無料
- AWS内部ネットワーク経由

### インターフェイス型

- 多数のAWSサービスに対応
- 時間単位の料金とデータ処理料金が発生
- プライベートIPアドレス経由

## Amazon CloudWatch Synthetics

- ウェブアプリケーションの稼働状況をユーザー視点で継続的に監視するマネージドサービス

## EC2 Instance Connect Endpoint

- VPC内に作成するリソースで、パブリックIPを持たないインスタンスへのSSH・RDP接続をAWSが管理するインフラ経由で仲介
