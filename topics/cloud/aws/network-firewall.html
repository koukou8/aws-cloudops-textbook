AWS Network Firewall

ヘッダーだけでなく通信の中身まで検査するDPIを、VPCの通信経路へ安全に挿入する方法を学びます。ファイアウォールの作成、ルール、AZごとのエンドポイント、往復ルートは一組です。

今回の設問の結論

AWS Network FirewallをVPCに構成し、ステートフルルールでインバウンド通信をDPIします。

ただし、ファイアウォールを作成しただけでVPC内の全通信が自動的に検査されるわけではありません。各AZの専用ファイアウォールサブネットにエンドポイントを置き、IGWとNLBの間を通る往復通信が同じAZのエンドポイントを通るようルートテーブルを構成します。

暗号化通信の注意：HTTPS/TLSのアプリケーション本文まで検査するには、ACMの証明書を使ったTLS inspection configurationで復号・検査・再暗号化を構成します。復号しない場合、暗号化された本文そのものは読めません。

基礎編：DPIと構成要素

1.1 DPIは通信のペイロードまで見る

セキュリティグループやネットワークACLは、主にIPアドレス、ポート、プロトコルなどを条件に通信を制御します。DPI（Deep Packet Inspection）はフローの状態とアプリケーションプロトコルを追跡し、復号可能な通信ではペイロードに含まれる攻撃シグネチャや不正なコマンド列まで評価します。

AWS Network FirewallはVPC向けのマネージド型ネットワークファイアウォール／IDS・IPSです。ステートフルエンジンにはSuricata互換ルールを使用でき、AWS管理ルールグループと独自ルールを組み合わせられます。

検査見る単位代表的な判断
ステートレス個々のパケット送信元／宛先、ポート、プロトコル
ステートフル往復のフロー接続状態、アプリケーションプロトコル
DPI再構成したフローと内容シグネチャ、不審なペイロード

Q1. DPIの特徴として最も適切なものは？

1.2 4つの部品を分けて考える

部品役割
Firewall保護対象VPCと利用するAZ／サブネットを定義
Firewall Policyステートレス・ステートフルルールと既定動作を束ねる
Rule Group一致条件とpass／alert／drop／reject等の動作を定義
Firewall Endpoint各AZの専用サブネットに置かれるルートの次ホップ

ファイアウォールエンドポイントを置くサブネットはNetwork Firewall専用にします。そのサブネット自身へ出入りする通信は検査対象にできないため、NLBやEC2など他のリソースを同居させません。

「VPCレベルのサービス」とは、一貫したポリシーをVPCへ適用できるという意味です。全通信を暗黙に横取りするという意味ではなく、検査したい通信をルートテーブルでエンドポイントへ送る必要があります。

IGWに関連付けるエッジルートテーブルで、NLB側サブネットのCIDR宛て通信を同じAZのファイアウォールエンドポイントへ送ります。ファイアウォールサブネットのルート表は検査後の通信をNLB側へ転送します。戻り通信も同じエンドポイントを経由してIGWへ戻します。

Network Firewall自体のためにNLBを置くわけではありません。NLBはアプリケーションの負荷分散、Network Firewallは経路上の検査という別の役割です。

段階導入：ルート変更は通信断を起こし得ます。各エンドポイントがREADYであること、ルールが想定どおりであること、戻り経路があることを検証してからAZ単位で切り替えます。

Q3. インバウンドDPIの経路として適切なのは？

2.2 AZローカルかつ対称なルーティング

Network Firewallは非対称ルーティングをサポートしません。要求と応答が同じファイアウォールエンドポイントを通らないと、状態テーブルが片方向しか認識できず、ステートフル検査やアプリケーション層の判定が正しく働きません。

2つのAZを使うなら、各AZに専用ファイアウォールサブネットとエンドポイントを1つずつ作り、AZ-Aのフローは往復ともAZ-A、AZ-Bのフローは往復ともAZ-Bを通す設計が基本です。NLBのクロスゾーン負荷分散を有効にする場合は、バックエンド向け経路も含めて非対称にならないか確認します。

確認点合格条件
配置利用する各AZに専用エンドポイントサブネット
往路IGWからAZローカルのendpointへ
復路同じendpointを通ってIGWへ
観測flow_idで要求・応答の両ログを確認

応用編：ルールとTLS検査

3.1 ステートレスで選別し、ステートフルで深く見る

ステートレスルールは個々のパケットを高速に評価します。DPIを行うフローは、ステートレスの既定動作またはルールからステートフルエンジンへ転送します。ステートフルルールではAWS管理ルールグループまたはSuricata互換ルールを使い、攻撃パターンに対してalert、drop、rejectなどの動作を定義できます。

本番導入では最初から大量にdropせず、まずalertで誤検知と業務影響を確認し、例外を整備してから段階的に遮断へ移すと安全です。ルール評価順序は、既定のaction orderかstrict orderのどちらを使うかをポリシー全体で統一します。

3.2 HTTPSの本文を見るにはTLS検査が必要

TLSで暗号化された通信は、通常のステートフル検査だけではアプリケーション本文をそのまま読めません。Network FirewallのTLS inspection configurationを使うと、対象フローを復号し、ステートフルルールで検査してから再暗号化できます。

インバウンドTLS検査では対象ドメインのサーバー証明書をACMで発行またはインポートし、検査対象のIP、ポート、プロトコル範囲を定義します。証明書の更新、対応TLS機能、プライバシー・法令、追加料金、レイテンシを事前に評価します。

NLBとの関係：NLBでTLSを終端するか、TCPでバックエンドへ透過するかにより、Network Firewallを通る時点の通信が暗号化済みかどうかが変わります。「DPIを導入した＝HTTPS本文を自動で読める」とは限りません。

実務編：他サービスとの違いと運用

4.1 似たサービスを目的で選ぶ

サービス方式インライン遮断今回
Network Firewall経路上でステートフル検査／DPIできる最適
GuardDutyCloudTrail、VPCフロー、DNS等を分析してFinding生成しない補完
Traffic Mirroring対応ENIの通信コピーを分析装置へ送るそれ自体はしない観測用途
AWS WAF対応するHTTP(S)入口でWebリクエストを検査できるNLBは直接の対象外
SG / NACLIP、ポート、プロトコル中心できるDPIではない

GuardDutyは脅威検出サービスとして重要ですが、通信経路へ入るプロキシではなく、ペイロードをインラインで遮断する製品ではありません。Traffic Mirroringはパケットのコピーを外部の監視装置へ送るため、フォレンジックや独自IDSには有効ですが、本番パスをその場で止めません。

Traffic MirroringではNetwork Load Balancerをミラーターゲットとして利用できますが、ミラーソースは対応するENIです。「NLBのインバウンド側へ設定すればDPI製品になる」という理解は誤りです。

4.2 導入と監視のチェックリスト

  1. 専用サブネットを各AZに用意

    NLBやEC2を同居させず、必要なIPアドレスを確保します。

  2. ルールグループとポリシーを作成

    既定動作、評価順序、管理ルール、独自Suricataルールを定義します。

  3. Firewallとendpointを作成

    各endpointがREADYになるまでルートを切り替えません。

  4. 往復ルートを段階的に変更

    IGW edge route tableとNLB側の戻り経路をAZ単位で検証します。

  5. ログとメトリクスを有効化

    Flow、Alert、必要に応じてTLSログをCloudWatch Logs、S3、Firehoseへ送り、drop増加やendpoint状態を監視します。

  6. テストして遮断へ移行

    alertで正常通信と誤検知を確認し、Reachability Analyzerやflow_idで対称性を確認します。

可用性だけでなく料金もAZ単位：エンドポイント時間料金、処理データ量、TLS高度検査、AZ間転送を見積もります。AZをまたぐ迂回は対称性・障害範囲・コストを悪化させます。

総合演習：NLBへのインバウンドDPI

設問を要件へ分解する

インターネットからIGW、NLBを経由して、2つのプライベートサブネットにあるEC2へ届く通信を対象とします。必要なのは「ペイロード検査」「既知シグネチャ」「通信経路上でのリアルタイム検査」です。

選択肢判定理由
GuardDuty不正解Findingを作る検出サービスで、インラインDPIではない
各プライベートサブネットに個別FW不正解専用endpointサブネットを各AZに置き、一つのポリシーと経路で保護する
VPCのNetwork Firewall＋stateful rules正解DPIとインライン遮断を提供。検査経路のルート設定も必要
NLBでTraffic Mirroring不正解コピー送信のみで、単独では分析・インライン遮断をしない
正解文の読み替え：「VPC全体に構成」は、全通信へ自動適用という意味ではありません。VPCのFirewall／Policyを作り、各AZの専用endpointを経由するルートへ変更した通信が検査対象です。

Q9. この要件を満たす最適なソリューションは？

覚えておく3行

  • Network FirewallはDPI可能だが、検査対象はendpointへルーティングした通信だけ。
  • 各AZの専用サブネットと、要求・応答が同じendpointを通る対称ルーティングが必要。
  • HTTPS本文の検査にはTLS inspection configurationとACM証明書が必要。
