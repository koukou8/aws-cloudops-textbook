基礎編：バケットにオブジェクトを保存する

1.1 S3はオブジェクトストレージ

Amazon Simple Storage Service（Amazon S3）は、ファイルの内容であるデータと、コンテンツタイプなどのメタデータを「オブジェクト」として保存します。オブジェクトはバケットに入り、キーによって識別されます。

サーバーのローカルディスクのような階層型ファイルシステムではありません。コンソールでフォルダーに見える区切りは、キーに含まれる / をプレフィックスとして表示したものです。

1.2 バケット名とリージョン

一般用途バケットは作成時にAWSリージョンを選びます。バケットに保存したオブジェクトは、明示的に転送やレプリケーションを設定しない限り、選択したリージョンに置かれます。

バケット名はグローバル名前空間で一意にします。名前に顧客名、メールアドレス、診療情報などを入れず、用途を推測しにくい命名にします。データ所在地、遅延、料金、法令を基にリージョンを決めます。

応用編：保存期間とアクセス頻度で設計する

2.1 ストレージクラスを選ぶ

料金は保存容量だけでなく、リクエスト、取り出し、最低保存期間、最小課金サイズ、データ転送も含めて比較します。アクセス頻度が読めない場合はS3 Intelligent-Tieringを候補にし、明確に低頻度・長期保管ならIA系やGlacier系を検討します。

クラス向くデータ注意点
S3 Standard頻繁に読む本番データ取り出し料金なし
Intelligent-Tieringアクセスパターンが変化・不明オブジェクト単位の監視・自動化料金
Standard-IA長期保存・低頻度だが即時取得取り出し料金と最低保存期間
Glacier系アーカイブ、バックアップクラスごとに取得時間と最低保存期間が異なる

2.2 バージョニングとライフサイクル

S3 Versioningを有効にすると、同じキーへの上書きは新しいバージョンとして保存され、通常の削除では削除マーカーが現在版になります。過去版を残せるため、誤削除や上書きから復旧しやすくなります。

各バージョンは差分ではなく完全なオブジェクトとして課金されます。S3 Lifecycleで、一定期間後のストレージクラス移行、非現行バージョンの期限切れ、不完全なマルチパートアップロードの中止を自動化します。

DAY 0Standard / Intelligent

直近の検査で参照される期間

DAY 90低頻度・アーカイブへ

要件に合うクラスへ移行

RETENTION END期限切れ

法令・社内規程に従い削除

3

実務編：安全にアップロード・運用する

3.1 公開を防ぎ、最小権限で許可する

S3バケットとオブジェクトは、明示的に許可しない限り非公開です。Block Public Accessを維持し、IAMポリシーとバケットポリシーで、必要な主体・操作・プレフィックスだけを許可します。

新規バケットではサーバー側暗号化が自動適用されます。管理要件に応じてSSE-S3またはAWS KMSキーを使うSSE-KMSを選び、通信はHTTPSを強制します。医療画像のような機微データでは、CloudTrailのデータイベントやS3のアクセスログ、Macieなども検討します。

CORSは認可ではありません。ブラウザーが異なるオリジンからS3へリクエストする際の許可ルールです。CORSを許可しても、IAMやバケットポリシーで許可されていない操作は成功しません。

3.2 長距離転送はTransfer Acceleration

S3 Transfer Accelerationは一般用途バケット単位で有効にし、bucket-name.s3-accelerate.amazonaws.com のような加速エンドポイントを使います。クライアントは近くのCloudFrontエッジロケーションへ接続し、そこからAWSの最適化されたネットワーク経路でバケットへ転送されます。利用者がCloudFrontディストリビューションを作成する仕組みではありません。

世界中から中央のバケットへアップロードするケースに向きます。追加料金があり、距離や回線によって効果が異なるため、AWSのSpeed Comparison toolや実データで測定します。バケット名にピリオドを含められない、仮想ホスト形式のリクエストが必要、対応リージョンを確認するといった前提条件もあります。

02 ENDPOINT加速用URLへ変更

03 MEASURE速度と費用を実測

拠点ごとに通常経路と比較して採用判断

実装上の要点：Transfer Accelerationを有効にしただけで、通常のリージョナルS3エンドポイントが自動的に高速化されるわけではありません。SDKの加速エンドポイント設定、または bucket-name.s3-accelerate.amazonaws.com を使用します。IPv4／IPv6の両方を使う場合は bucket-name.s3-accelerate.dualstack.amazonaws.com を選べます。

3.3 大容量はマルチパート、直接投稿は署名付きURL

マルチパートアップロードは、1つの大きなオブジェクトを複数のパートへ分けて並列送信します。一部が失敗しても該当パートだけを再送でき、AWSは100MB以上のオブジェクトで利用を推奨しています。

Webアプリのサーバーを画像データが通過しない構成では、バックエンドが短い有効期限と限定したキーを持つ署名付きURLを発行し、クライアントがS3へ直接PUTできます。URLは発行者の権限を一時的に委任するため、ログ、サイズ・形式検査、キー生成、失効時間を慎重に設計します。

追加演習：レプリケーション、Object Lock、版管理

CRRで既定に複製されるもの

ライブレプリケーションはルール作成後の対象オブジェクトを複製し、オブジェクト本体に加えてメタデータ、ACL更新、オブジェクトタグなども扱います。既存オブジェクトはS3 Batch Replicationを使います。Glacier Flexible Retrieval／Deep Archive等に格納済みのソースオブジェクトは、復元して別ストレージクラスへコピーするまで複製できません。

出典：S3が複製するもの

Governanceモードの保持を正当にバイパスする

対象バージョンを永久削除する主体にはs3:BypassGovernanceRetentionとs3:DeleteObjectVersionを許可し、delete-object --version-id ... --bypass-governance-retentionのように明示します。バージョンIDなしの削除は削除マーカーを作るだけです。リーガルホールドが有効なら、Governanceのバイパスとは別に解除が必要です。

同じリージョンで誤上書き・削除から守る

S3バージョニングで旧バージョンを保持し、ライフサイクルのNoncurrentVersionExpirationで非現行バージョンを120日後に削除します。CRRは別リージョン要件、MFA Deleteは日常運用の自動整理とは別の制御です。
